**Data flow and clocking summary:**

- **100 MHz system clock (`clk`)** — drives `camera_config`, `frame_capture`, `pixel_capture`, `uart_print`, `uart_tx`, and BRAM **port A** (write).
- **25 MHz pixel clock (`pclk_25`)** — generated by `clk_div` (divide-by-4). Drives `vga_sync` and BRAM **port B** (read). Also fed to OV7670 `XCLK`, so the camera's pixel clock `PCLK` runs at ~25 MHz too.
- **SCCB (~100 kHz SCL)** — generated by `sccb_master` (CLKDIV = 250 from 100 MHz), used once at boot to load 33 OV7670 registers.
- **Camera output** — QVGA 320×240 RGB565 streaming at ~30 fps. `frame_capture` samples each `PCLK` rising edge inside `HREF`, combines two bytes into one pixel, drops the LSB of each channel to produce RGB444, and writes it into BRAM at `wr_addr = row × 320 + col`.
- **Display side** — `vga_sync` produces 640×480 @ 60 Hz timing. For every visible pixel, `top.v` computes a read address into the frame buffer that implements **2× pixel doubling + 90° CW rotation** (the camera is physically mounted rotated 90° CCW). After 1 cycle of BRAM read latency, the pixel is passed through `filters` (selected by `SW[1:0]` and `SW[4:2]`) and driven onto `vga_r/g/b`.

**Data transfer frequency:**

| Path | Clock | Effective rate |
|---|---|---|
| OV7670 → BRAM (port A write) | 100 MHz `clk` | 1 pixel every 4 PCLK ticks ≈ 6.25 Mpix/s (2 bytes per pixel @ 25 MHz PCLK) |
| BRAM (port B read) → VGA | 25 MHz `pclk_25` | 1 pixel / cycle = 25 Mpix/s peak (active 640×480×60 ≈ 18.4 Mpix/s) |
| SCCB config | ~100 kHz SCL | 33 register writes, one-shot at boot |
| UART debug | 100 MHz `clk` | 115 200 baud, 1 pixel/frame ≈ 30 pixels/s |

## Design Decision

### 1. Why a true dual-port BRAM (independent clocks) for the frame buffer

**Reason:**
- The OV7670 capture side runs in the 100 MHz system domain (after a 3-stage synchronizer on `PCLK`/`VSYNC`/`HREF`/`DATA`).
- The VGA side must read on the 25 MHz pixel clock to stay locked to 640×480 @ 60 Hz timing.
- Putting the clock-domain crossing **inside the BRAM** (a single hardware structure that already supports per-port clocks) is cheaper and safer than building an external async FIFO.

**Why simple dual-port (not true dual-port read/write on both sides):**
- `frame_capture` only ever writes, `vga_sync`/scaler only ever reads → no conflict possible, no arbitration needed.
- We use Vivado's `(* ram_style = "block" *)` attribute to force BRAM inference rather than distributed RAM. 320 × 240 × 12 bits = 900 Kbit ≈ 25 of the 18 Kb block RAMs on Basys 3.

**Why native interface (not AXI):**
- Lower complexity and fewer LUTs/FFs. AXI's handshake/burst features are unnecessary because both ports drive a fixed pixel rate.

### 2. Why store RGB444 (12-bit) instead of the camera-native RGB565

**Reason:**
- The Basys 3 VGA connector physically supports only 4 bits per channel (resistor-DAC). The lower bits of RGB565 would be discarded at the VGA output anyway.
- Cutting the buffer width from 16 → 12 bits reduces BRAM usage by 25 % while losing no visible information.
- The packing is done in-line inside `frame_capture` (just bit-slicing) — no multiplier or LUT cost.

### 3. Why 25 MHz pixel clock and shared XCLK

**Reason:**
- Standard VGA 640×480 @ 60 Hz **requires** a 25.175 MHz pixel clock. Dividing 100 MHz by 4 gives 25.0 MHz — within the 0.7 % tolerance most CRT/LCD monitors accept.
- The OV7670 accepts XCLK anywhere from 10–48 MHz; 25 MHz is in the sweet spot and conveniently matches our pixel clock, so we use a single divider instead of two.
- At 25 MHz XCLK, the camera's `PCLK` is also ~25 MHz, giving a comfortable ~33 ms/frame at QVGA — well below the BRAM write bandwidth.

### 4. Why SCCB at ~100 kHz

**Reason:**
- The OV7670 SCCB spec lists a maximum of 400 kHz, but the camera works most reliably at 100 kHz (matches standard I²C low-speed timing the OmniVision app notes use).
- 100 MHz / (4 × 250) = 100 kHz — picked by `sccb_master`'s `CLKDIV = 250` parameter.
- Configuration is one-shot (≈ 33 register writes in <50 ms), so SCL speed has zero runtime cost.

### 5. Why an integer 2× pixel-doubling scaler with crop, not fractional scaling

**Reason:**
- The captured frame is 320×240; the screen is 640×480 — exactly 2× in both axes, so integer doubling gives a clean image with no row/column dropping (which would otherwise cause visible staircase or shimmer).
- The camera is physically mounted rotated 90° CCW, so the **read address** is rotated 90° CW (`cam_row = 239 − img_x`, `cam_col = img_y + 40`). Doing the rotation on read side is free — it's just address arithmetic, no extra memory needed.
- After rotation, the image is 240 wide × 320 tall (portrait). Doubled, it becomes 480 × 640, which is taller than the 480-line screen, so we crop 40 rotated rows top & bottom. The 480×480 result is centered horizontally with 80-pixel black bars on each side.
- All address math uses shifts and adds (`cam_row << 8 + cam_row << 6 + cam_col` = `cam_row × 320 + cam_col`) — **no multiplier inferred**.

### 6. Why a single combinational filter mux (not pipelined)

**Reason:**
- The four filter modes (raw, grayscale, invert, channel-isolate) are all sub-pixel-level operations: shifts, adds, ANDs. Combinational delay on 12-bit data is well under one 25 MHz period (40 ns).
- A registered version would add a 1-pixel horizontal shift relative to the BRAM read latency — handled separately by `in_image_d`, but adding more registers would complicate the alignment for no benefit.

### 7. Why 3-stage synchronizers on every camera-domain signal

**Reason:**
- `cam_pclk`, `cam_vsync`, `cam_href`, and `cam_data[7:0]` are asynchronous to the 100 MHz system clock.
- Two flip-flops handle metastability; the third stage is used to **detect edges** (`pclk_rise`, `vsync_fall`, `href_fall`) by comparing stage 2 vs stage 3. This avoids spurious edges that a 2-stage synchronizer can produce.
- The same pattern is repeated in `pixel_capture` and `frame_capture` for consistency.

### 8. Why a separate `pixel_capture` + UART debug path

**Reason:**
- Bring-up sanity: it samples one pixel from the **center** of the frame (line 120, pixel 160) once per frame and prints it as ASCII hex (`"PX: AABB\r\n"`) over USB-UART at 115 200 baud.
- This is independent of the BRAM/VGA pipeline, so it lets us confirm the camera and SCCB config are working even if the VGA side is broken. Costs almost nothing in LUTs and is invaluable for debugging on real hardware.

### 9. Why LED status bits

**Reason:**
- Sticky `config_done`, `vsync_seen`, `href_seen`, `pclk_seen` LEDs give an at-a-glance health check on the board with no extra equipment. `frame_done` toggles every captured frame, giving a visible ~30 Hz heartbeat to confirm the capture FSM is reaching end-of-frame.

### 10. Resource utilization summary

| Resource | Where it's spent | Notes |
|---|---|---|
| BRAM | `frame_buffer` (~25 × 18 Kb blocks) | Dominant memory cost. Justified — 320×240 frame can't fit in distributed RAM. |
| LUTs/FFs | FSMs (`sccb_master`, `frame_capture`, `camera_config`, `uart_print`), synchronizers, VGA counters | All small, sequential, no multipliers. |
| DSP | **None inferred.** All address math is shifts + adds. | Deliberate — `row × 320` is precomputed (`row_base`) and updated by +320 each line. |
| Clock resources | One MMCM-free `clk_div` (toggle FF) for 25 MHz | Could be a MMCM for an exact 25.175 MHz, but the integer divide works fine on every monitor we tested. |

## Implementation Detail

### Module : `clk_div`

**Module code:**
```verilog
module clk_div (
    input  wire clk_100mhz,   // 100MHz system clock from Basys 3
    input  wire rst,           // Active-high reset
    output reg  xclk           // ~25MHz output to OV7670 XCLK pin
);

    reg [1:0] counter;

    always @(posedge clk_100mhz or posedge rst) begin
        if (rst) begin
            counter <= 2'd0;
            xclk    <= 1'b0;
        end else begin
            if (counter == 2'd1) begin
                counter <= 2'd0;
                xclk    <= ~xclk;   // Toggle every 2 cycles = divide by 4 = 25MHz
            end else begin
                counter <= counter + 1;
            end
        end
    end

endmodule
```

**Module description:**
Divides the 100 MHz Basys 3 system clock by 4 to produce a 25 MHz clock. The output is used both as the VGA pixel clock and as the OV7670 `XCLK` reference, so the camera's `PCLK` also runs at ~25 MHz.

### Module : `sccb_master`

**Module code:**
```verilog
module sccb_master #(
    parameter CLKDIV = 250   // Divider to produce ~100kHz SCL from 100MHz clk
)(
    input  wire       clk,
    input  wire       rst,
    input  wire       start,
    input  wire [7:0] reg_addr,
    input  wire [7:0] reg_data,
    output reg        done,
    output reg        scl,
    output reg        sda
);

    localparam IDLE       = 4'd0;
    localparam START_BIT  = 4'd1;
    localparam SEND_BYTE  = 4'd2;
    localparam DONT_CARE  = 4'd3;
    localparam NEXT_PHASE = 4'd4;
    localparam STOP_BIT   = 4'd5;
    localparam DONE_STATE = 4'd6;

    reg [3:0]  state;
    reg [3:0]  bit_index;
    reg [1:0]  phase;
    reg [7:0]  shift_reg;
    reg [8:0]  clk_cnt;
    reg        clk_tick;
    reg [1:0]  tick_cnt;

    // Quarter-period clock-tick generator (4 ticks per SCL cycle)
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            clk_cnt  <= 9'd0;
            clk_tick <= 1'b0;
        end else if (clk_cnt == CLKDIV - 1) begin
            clk_cnt  <= 9'd0;
            clk_tick <= 1'b1;
        end else begin
            clk_cnt  <= clk_cnt + 1;
            clk_tick <= 1'b0;
        end
    end

    // SCCB FSM: START → 3× (SEND_BYTE → DONT_CARE) → STOP
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            state <= IDLE; scl <= 1'b1; sda <= 1'b1;
            done  <= 1'b0; bit_index <= 4'd7; phase <= 2'd0;
            shift_reg <= 8'd0; tick_cnt <= 2'd0;
        end else begin
            done <= 1'b0;
            case (state)
                IDLE: begin
                    scl <= 1'b1; sda <= 1'b1;
                    if (start) begin
                        phase     <= 2'd0;
                        shift_reg <= 8'h42;   // OV7670 write address
                        bit_index <= 4'd7;
                        tick_cnt  <= 2'd0;
                        state     <= START_BIT;
                    end
                end
                START_BIT: if (clk_tick) begin
                    tick_cnt <= tick_cnt + 1;
                    case (tick_cnt)
                        2'd0: begin scl <= 1'b1; sda <= 1'b1; end
                        2'd1: begin scl <= 1'b1; sda <= 1'b0; end
                        2'd2: begin scl <= 1'b0; sda <= 1'b0; end
                        2'd3: begin tick_cnt <= 2'd0; state <= SEND_BYTE; end
                    endcase
                end
                SEND_BYTE: if (clk_tick) begin
                    tick_cnt <= tick_cnt + 1;
                    case (tick_cnt)
                        2'd0: begin scl <= 1'b0; sda <= shift_reg[bit_index]; end
                        2'd1: scl <= 1'b1;
                        2'd2: scl <= 1'b1;
                        2'd3: begin
                            scl <= 1'b0; tick_cnt <= 2'd0;
                            if (bit_index == 0) state <= DONT_CARE;
                            else                bit_index <= bit_index - 1;
                        end
                    endcase
                end
                DONT_CARE: if (clk_tick) begin
                    tick_cnt <= tick_cnt + 1;
                    case (tick_cnt)
                        2'd0: begin scl <= 1'b0; sda <= 1'b1; end
                        2'd1: scl <= 1'b1;
                        2'd2: scl <= 1'b1;
                        2'd3: begin scl <= 1'b0; tick_cnt <= 2'd0; state <= NEXT_PHASE; end
                    endcase
                end
                NEXT_PHASE: begin
                    phase     <= phase + 1;
                    bit_index <= 4'd7;
                    tick_cnt  <= 2'd0;
                    case (phase)
                        2'd0: begin shift_reg <= reg_addr; state <= SEND_BYTE; end
                        2'd1: begin shift_reg <= reg_data; state <= SEND_BYTE; end
                        2'd2: state <= STOP_BIT;
                        default: state <= STOP_BIT;
                    endcase
                end
                STOP_BIT: if (clk_tick) begin
                    tick_cnt <= tick_cnt + 1;
                    case (tick_cnt)
                        2'd0: begin scl <= 1'b0; sda <= 1'b0; end
                        2'd1: begin scl <= 1'b1; sda <= 1'b0; end
                        2'd2: begin scl <= 1'b1; sda <= 1'b1; end
                        2'd3: begin tick_cnt <= 2'd0; state <= DONE_STATE; end
                    endcase
                end
                DONE_STATE: begin done <= 1'b1; state <= IDLE; end
                default: state <= IDLE;
            endcase
        end
    end
endmodule
```

**Module description:**
Implements the SCCB (Serial Camera Control Bus) write protocol used to configure OV7670 registers. SCCB is I²C-like but has no ACK — instead it inserts a "don't-care" bit between bytes. Each transaction is the 3-byte sequence `[0x42 device-write-address] → [register address] → [register data]`, surrounded by standard START/STOP conditions. The internal clock-tick generator divides the 100 MHz system clock by `CLKDIV = 250` to produce 4 ticks per SCL bit period, giving an SCL frequency of ~100 kHz.

### Module : `camera_config`

**Module code:**
```verilog
module camera_config (
    input  wire clk,
    input  wire rst,
    output wire scl,
    output wire sda,
    output reg  config_done
);

    reg [15:0] config_rom [0:39];

    initial begin
        // Soft reset
        config_rom[0]  = 16'h1280; // COM7: full reset
        // Output format: QVGA RGB565
        config_rom[1]  = 16'h1214; // COM7: QVGA + RGB
        config_rom[2]  = 16'h40D0; // COM15: full range + RGB565
        config_rom[3]  = 16'h3A04; // TSLB
        // QVGA scaling
        config_rom[4]  = 16'h0C08;
        config_rom[5]  = 16'h3E00;
        config_rom[6]  = 16'h1100;
        // AWB + AEC + AGC enabled
        config_rom[7]  = 16'h13E7;
        // Brightness defaults
        config_rom[8]  = 16'h0000;
        config_rom[9]  = 16'h1000;
        config_rom[10] = 16'h1E07;
        // Color matrix (OmniVision reference, MTXS bit 7 set)
        config_rom[11] = 16'h4FB3;
        config_rom[12] = 16'h50B3;
        config_rom[13] = 16'h5100;
        config_rom[14] = 16'h523D;
        config_rom[15] = 16'h53A7;
        config_rom[16] = 16'h54E4;
        config_rom[17] = 16'h589E;
        // Gamma curve
        config_rom[18] = 16'h7A20; config_rom[19] = 16'h7B10;
        config_rom[20] = 16'h7C1E; config_rom[21] = 16'h7D35;
        config_rom[22] = 16'h7E5A; config_rom[23] = 16'h7F69;
        config_rom[24] = 16'h8076; config_rom[25] = 16'h8180;
        config_rom[26] = 16'h8288; config_rom[27] = 16'h838F;
        config_rom[28] = 16'h8496;
        // Scaling defaults
        config_rom[29] = 16'h703A;
        config_rom[30] = 16'h7135;
        // AGC cap + UV auto adjust
        config_rom[31] = 16'h1408;
        config_rom[32] = 16'h3DC0;
        // End sentinel
        config_rom[33] = 16'hFFFF;
        // ... remaining entries 16'hFFFF
    end

    localparam S_RESET_SEND = 3'd0, S_RESET_DONE = 3'd1, S_RESET_WAIT = 3'd2;
    localparam S_LOAD       = 3'd3, S_WRITE      = 3'd4, S_WAIT_DONE  = 3'd5;
    localparam S_PAUSE      = 3'd6, S_DONE       = 3'd7;

    reg [2:0]  state;
    reg [5:0]  rom_index;
    reg [7:0]  reg_addr_r, reg_data_r;
    reg        sccb_start;
    wire       sccb_done;
    reg [24:0] wait_cnt;
    localparam RESET_WAIT_CYCLES = 25'd2_000_000;
    localparam PAUSE_CYCLES      = 25'd100_000;

    sccb_master #(.CLKDIV(250)) u_sccb (
        .clk(clk), .rst(rst), .start(sccb_start),
        .reg_addr(reg_addr_r), .reg_data(reg_data_r),
        .done(sccb_done), .scl(scl), .sda(sda)
    );

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            state <= S_RESET_SEND; rom_index <= 6'd0;
            sccb_start <= 1'b0; config_done <= 1'b0;
            wait_cnt <= 25'd0; reg_addr_r <= 0; reg_data_r <= 0;
        end else begin
            sccb_start <= 1'b0;
            case (state)
                S_RESET_SEND: begin
                    reg_addr_r <= config_rom[0][15:8];
                    reg_data_r <= config_rom[0][7:0];
                    sccb_start <= 1'b1;
                    rom_index  <= 6'd1;
                    state      <= S_RESET_DONE;
                end
                S_RESET_DONE: if (sccb_done) begin
                    wait_cnt <= 25'd0; state <= S_RESET_WAIT;
                end
                S_RESET_WAIT: if (wait_cnt < RESET_WAIT_CYCLES) wait_cnt <= wait_cnt + 1;
                              else begin wait_cnt <= 25'd0; state <= S_LOAD; end
                S_LOAD: begin
                    if (config_rom[rom_index] == 16'hFFFF) state <= S_DONE;
                    else begin
                        reg_addr_r <= config_rom[rom_index][15:8];
                        reg_data_r <= config_rom[rom_index][7:0];
                        rom_index  <= rom_index + 1;
                        state      <= S_WRITE;
                    end
                end
                S_WRITE:     begin sccb_start <= 1'b1; state <= S_WAIT_DONE; end
                S_WAIT_DONE: if (sccb_done) begin wait_cnt <= 25'd0; state <= S_PAUSE; end
                S_PAUSE:     if (wait_cnt < PAUSE_CYCLES) wait_cnt <= wait_cnt + 1;
                             else begin wait_cnt <= 25'd0; state <= S_LOAD; end
                S_DONE:      config_done <= 1'b1;
                default:     state <= S_DONE;
            endcase
        end
    end
endmodule
```

**Module description:**
At power-on, sequentially writes 33 OV7670 register/value pairs through `sccb_master` to configure the camera for QVGA (320×240) RGB565 output with AWB / AEC / AGC enabled, the OmniVision reference color-matrix coefficients, a gamma curve, and an AGC ceiling of 2× to keep noise low. A long delay (~20 ms at 100 MHz) follows the soft reset (`COM7 = 0x80`) before the rest of the register stream is sent, and ~1 ms separates each subsequent write. When the sentinel `0xFFFF` is reached, `config_done` is asserted permanently and the rest of the pipeline starts.

### Module : `frame_capture`

**Module code:**
```verilog
module frame_capture #(
    parameter H_PIXELS = 320,
    parameter V_PIXELS = 240,
    parameter ADDR_W   = 17
)(
    input  wire              clk,           // 100 MHz system clock
    input  wire              rst,
    input  wire              config_done,

    // OV7670 (asynchronous)
    input  wire              cam_pclk,
    input  wire              cam_vsync,
    input  wire              cam_href,
    input  wire [7:0]        cam_data,

    // BRAM write port (synchronous to clk)
    output reg  [ADDR_W-1:0] wr_addr,
    output reg  [11:0]       wr_data,
    output reg               wr_en,
    output reg               frame_done
);

    // 3-stage synchronizers
    reg pclk_r1,  pclk_r2,  pclk_r3;
    reg vsync_r1, vsync_r2, vsync_r3;
    reg href_r1,  href_r2,  href_r3;
    reg [7:0] data_r1, data_r2, data_r3;

    always @(posedge clk) begin
        pclk_r1  <= cam_pclk;  pclk_r2  <= pclk_r1;  pclk_r3  <= pclk_r2;
        vsync_r1 <= cam_vsync; vsync_r2 <= vsync_r1; vsync_r3 <= vsync_r2;
        href_r1  <= cam_href;  href_r2  <= href_r1;  href_r3  <= href_r2;
        data_r1  <= cam_data;  data_r2  <= data_r1;  data_r3  <= data_r2;
    end

    wire pclk_rise  = ( pclk_r2  && !pclk_r3);
    wire vsync_rise = ( vsync_r2 && !vsync_r3);
    wire vsync_fall = (!vsync_r2 &&  vsync_r3);
    wire href_fall  = (!href_r2  &&  href_r3);

    reg        byte_sel;
    reg [7:0]  byte_high;
    reg [8:0]         row_cnt;
    reg [9:0]         col_cnt;
    reg [ADDR_W-1:0]  row_base;   // row_cnt * H_PIXELS, maintained by +320 each line

    localparam S_WAIT_CONFIG = 2'd0, S_WAIT_FRAME = 2'd1, S_CAPTURE = 2'd2;
    reg [1:0] state;

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            state <= S_WAIT_CONFIG;
            wr_addr <= 0; wr_data <= 0; wr_en <= 0; frame_done <= 0;
            byte_sel <= 0; byte_high <= 0;
            row_cnt <= 0; col_cnt <= 0; row_base <= 0;
        end else begin
            wr_en      <= 1'b0;
            frame_done <= 1'b0;
            case (state)
                S_WAIT_CONFIG: if (config_done) state <= S_WAIT_FRAME;

                S_WAIT_FRAME: if (vsync_fall) begin
                    row_cnt  <= 0; col_cnt <= 0; row_base <= 0;
                    byte_sel <= 0; state   <= S_CAPTURE;
                end

                S_CAPTURE: begin
                    if (vsync_rise) begin
                        frame_done <= 1'b1;
                        state      <= S_WAIT_FRAME;
                    end else if (href_fall) begin
                        col_cnt  <= 0; byte_sel <= 0;
                        if (row_cnt < V_PIXELS - 1) begin
                            row_cnt  <= row_cnt + 1;
                            row_base <= row_base + H_PIXELS;
                        end
                    end else if (pclk_rise && href_r2 &&
                                 col_cnt < H_PIXELS && row_cnt < V_PIXELS) begin
                        if (byte_sel == 1'b0) begin
                            byte_high <= data_r3;
                            byte_sel  <= 1'b1;
                        end else begin
                            // RGB565 → RGB444 (drop LSB of each channel)
                            wr_data <= { byte_high[7:4],
                                         byte_high[2:0], data_r3[7],
                                         data_r3[4:1] };
                            wr_addr <= row_base + col_cnt;
                            wr_en   <= 1'b1;
                            col_cnt <= col_cnt + 1;
                            byte_sel<= 1'b0;
                        end
                    end
                end
                default: state <= S_WAIT_CONFIG;
            endcase
        end
    end
endmodule
```

**Module description:**
Streams pixels from the OV7670 into the dual-port BRAM. All camera-domain signals (`PCLK`, `VSYNC`, `HREF`, `DATA[7:0]`) are 3-stage synchronized into the 100 MHz domain, with edges detected by comparing stages 2 and 3. The FSM waits for `config_done`, then aligns to a `VSYNC` falling edge to mark the start of a frame. Inside a line (`HREF` high), each pair of `PCLK`-sampled bytes is combined into one 16-bit RGB565 pixel, then re-packed into 12-bit RGB444 (top 4 bits of each channel) and written to BRAM at `wr_addr = row_base + col_cnt`. Rows are aligned to `HREF` falling edges and `row_base` is incremented by 320 each line — so any extra bytes the camera produces within a line are dropped rather than causing diagonal skew.

module frame_buffer (

### Module : `vga_sync`

**Module code:**
```verilog
module vga_sync (
    input  wire       clk,        // 25 MHz pixel clock
    input  wire       reset,
    output wire       hsync,
    output wire       vsync,
    output wire [9:0] pixel_x,
    output wire [9:0] pixel_y,
    output wire       video_active
);
    // 640×480 @ 60 Hz timing
    localparam H_VISIBLE = 640, H_FRONT = 16, H_SYNC = 96, H_BACK = 48;
    localparam H_TOTAL   = 800;
    localparam V_VISIBLE = 480, V_FRONT = 10, V_SYNC = 2,  V_BACK = 33;
    localparam V_TOTAL   = 525;

    reg [9:0] h_count = 0;
    reg [9:0] v_count = 0;

    always @(posedge clk) begin
        if (reset) h_count <= 0;
        else if (h_count == H_TOTAL - 1) h_count <= 0;
        else h_count <= h_count + 1;
    end

    always @(posedge clk) begin
        if (reset) v_count <= 0;
        else if (h_count == H_TOTAL - 1) begin
            if (v_count == V_TOTAL - 1) v_count <= 0;
            else                        v_count <= v_count + 1;
        end
    end

    // Active-low sync pulses
    assign hsync = ~((h_count >= H_VISIBLE + H_FRONT) &&
                     (h_count <  H_VISIBLE + H_FRONT + H_SYNC));
    assign vsync = ~((v_count >= V_VISIBLE + V_FRONT) &&
                     (v_count <  V_VISIBLE + V_FRONT + V_SYNC));

    assign pixel_x = h_count;
    assign pixel_y = v_count;
    assign video_active = (h_count < H_VISIBLE) && (v_count < V_VISIBLE);
endmodule
```

**Module description:**
Generates standard VGA 640×480 @ 60 Hz timing on a 25 MHz pixel clock. Two counters (`h_count`, `v_count`) cycle through 800 × 525 total pixels per frame. `hsync` and `vsync` are produced as active-low pulses inside the blanking intervals. `pixel_x` / `pixel_y` expose the current pixel coordinate, and `video_active` is high only inside the 640×480 visible region. These signals drive both the pixel-address logic in `top.v` and the VGA connector.

### Module : `filters`

**Module code:**
```verilog
module filters (
    input  [11:0] pixel_in,
    input  [4:0]  sw,
    output [11:0] pixel_out
);
    wire [3:0] red_in   = pixel_in[11:8];
    wire [3:0] green_in = pixel_in[7:4];
    wire [3:0] blue_in  = pixel_in[3:0];

    // Grayscale: 0.25·R + 0.5·G + 0.25·B (luma approximation in 4-bit)
    wire [3:0] gray = (red_in >> 2) + (green_in >> 1) + (blue_in >> 2);

    // Invert
    wire [11:0] inverted = ~pixel_in;

    // Channel isolate
    wire [3:0] isolated_red   = sw[2] ? red_in   : 4'b0;
    wire [3:0] isolated_green = sw[3] ? green_in : 4'b0;
    wire [3:0] isolated_blue  = sw[4] ? blue_in  : 4'b0;
    wire [11:0] isolated = {isolated_red, isolated_green, isolated_blue};

    // Mode select via SW[1:0]
    assign pixel_out = (sw[1:0] == 2'b00) ? pixel_in :
                       (sw[1:0] == 2'b01) ? {gray, gray, gray} :
                       (sw[1:0] == 2'b10) ? inverted :
                                            isolated;
endmodule
```

**Module description:**
Combinational pixel-level filter mux that runs in the VGA pixel domain. `SW[1:0]` selects one of four modes: raw pass-through, grayscale (a fixed-point ≈ 0.25 R + 0.5 G + 0.25 B replicated to all channels), bit-wise inversion, or channel-isolation. In isolation mode, `SW[4:2]` chooses which of red / green / blue channels survive — the others are zeroed. Because everything is shifts, adds, and bit-wise gates on 4-bit values, the entire path is far under one 25 MHz period and needs no pipelining.

### Module : `pixel_capture`

**Module code:**
```verilog
module pixel_capture (
    input  wire        clk,
    input  wire        rst,
    input  wire        config_done,
    input  wire        cam_pclk,
    input  wire        cam_vsync,
    input  wire        cam_href,
    input  wire [7:0]  cam_data,
    output reg  [15:0] pixel_data,
    output reg         pixel_valid
);
    // 3-stage synchronizers (identical pattern to frame_capture)
    reg pclk_r1,  pclk_r2,  pclk_r3;
    reg vsync_r1, vsync_r2, vsync_r3;
    reg href_r1,  href_r2,  href_r3;
    reg [7:0] data_r1, data_r2;
    always @(posedge clk) begin
        pclk_r1  <= cam_pclk;  pclk_r2  <= pclk_r1;  pclk_r3  <= pclk_r2;
        vsync_r1 <= cam_vsync; vsync_r2 <= vsync_r1; vsync_r3 <= vsync_r2;
        href_r1  <= cam_href;  href_r2  <= href_r1;  href_r3  <= href_r2;
        data_r1  <= cam_data;  data_r2  <= data_r1;
    end
    wire pclk_rise  = ( pclk_r2  && !pclk_r3);
    wire vsync_fall = (!vsync_r2 &&  vsync_r3);
    wire vsync_rise = ( vsync_r2 && !vsync_r3);
    wire href_rise  = ( href_r2  && !href_r3);
    wire href_fall  = (!href_r2  &&  href_r3);

    localparam [8:0] TARGET_LINE  = 9'd120;
    localparam [9:0] TARGET_PIXEL = 10'd160;
    localparam [9:0] TARGET_BYTE  = TARGET_PIXEL * 2;

    reg [8:0] line_cnt;
    reg [9:0] byte_cnt;
    reg [7:0] byte0;

    localparam S_WAIT_CONFIG=3'd0, S_WAIT_FRAME=3'd1, S_COUNT_LINES=3'd2,
               S_COUNT_BYTES=3'd3, S_GRAB_BYTE1=3'd4, S_IDLE=3'd5;
    reg [2:0] state;

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            state <= S_WAIT_CONFIG; pixel_data <= 0; pixel_valid <= 0;
            byte0 <= 0; line_cnt <= 0; byte_cnt <= 0;
        end else begin
            pixel_valid <= 1'b0;
            case (state)
                S_WAIT_CONFIG: if (config_done) state <= S_WAIT_FRAME;
                S_WAIT_FRAME:  if (vsync_fall) begin
                    line_cnt <= 0; byte_cnt <= 0; state <= S_COUNT_LINES;
                end
                S_COUNT_LINES: if (vsync_rise) state <= S_WAIT_FRAME;
                               else if (href_rise) begin
                                   if (line_cnt == TARGET_LINE) begin
                                       byte_cnt <= 0; state <= S_COUNT_BYTES;
                                   end else line_cnt <= line_cnt + 1;
                               end
                S_COUNT_BYTES: if (href_fall) state <= S_WAIT_FRAME;
                               else if (pclk_rise && href_r2) begin
                                   if (byte_cnt == TARGET_BYTE) begin
                                       byte0 <= data_r2; state <= S_GRAB_BYTE1;
                                   end else byte_cnt <= byte_cnt + 1;
                               end
                S_GRAB_BYTE1: if (pclk_rise && href_r2) begin
                                  pixel_data  <= {byte0, data_r2};
                                  pixel_valid <= 1'b1;
                                  state       <= S_IDLE;
                              end
                S_IDLE: if (vsync_fall) begin
                            line_cnt <= 0; byte_cnt <= 0; state <= S_COUNT_LINES;
                        end
                default: state <= S_WAIT_CONFIG;
            endcase
        end
    end
endmodule
```

**Module description:**
Debug-only path used during bring-up. Samples a single pixel per frame at the center of the QVGA frame (line 120, pixel 160), then asserts `pixel_valid` for one cycle with the raw 16-bit RGB565 value on `pixel_data`. Independent of the BRAM/VGA pipeline, so it can verify camera and SCCB configuration even when the display side is not working. The 3-stage synchronizer pattern is identical to `frame_capture`.

### Module : `uart_tx`

**Module code:**
```verilog
module uart_tx #(
    parameter BAUD_DIV = 868     // 100 MHz / 115200 baud
)(
    input  wire       clk,
    input  wire       rst,
    input  wire [7:0] data_in,
    input  wire       send,
    output reg        tx,
    output reg        busy
);
    localparam IDLE  = 2'd0, START = 2'd1, DATA = 2'd2, STOP = 2'd3;

    reg [1:0]  state;
    reg [9:0]  baud_cnt;
    reg [3:0]  bit_cnt;
    reg [7:0]  shift_reg;

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            state <= IDLE; tx <= 1'b1; busy <= 1'b0;
            baud_cnt <= 0; bit_cnt <= 0; shift_reg <= 0;
        end else case (state)
            IDLE: begin
                tx <= 1'b1; busy <= 1'b0;
                if (send) begin
                    shift_reg <= data_in; baud_cnt <= 0;
                    busy <= 1'b1; state <= START;
                end
            end
            START: begin
                tx <= 1'b0;
                if (baud_cnt == BAUD_DIV - 1) begin
                    baud_cnt <= 0; bit_cnt <= 0; state <= DATA;
                end else baud_cnt <= baud_cnt + 1;
            end
            DATA: begin
                tx <= shift_reg[0];
                if (baud_cnt == BAUD_DIV - 1) begin
                    baud_cnt  <= 0;
                    shift_reg <= {1'b0, shift_reg[7:1]};
                    if (bit_cnt == 7) state <= STOP;
                    else              bit_cnt <= bit_cnt + 1;
                end else baud_cnt <= baud_cnt + 1;
            end
            STOP: begin
                tx <= 1'b1;
                if (baud_cnt == BAUD_DIV - 1) begin
                    baud_cnt <= 0; state <= IDLE;
                end else baud_cnt <= baud_cnt + 1;
            end
            default: state <= IDLE;
        endcase
    end
endmodule
```

**Module description:**
8N1 UART transmitter. Asserting `send` for one cycle latches `data_in`, drops the line for one start bit, shifts the 8 data bits out LSB-first, and finally drives a stop bit. `BAUD_DIV` is set to 868 — at 100 MHz this gives the standard 115 200 baud rate used by the Basys 3 USB-UART bridge.

### Module : `uart_print`

**Module code:**
```verilog
module uart_print (
    input  wire        clk,
    input  wire        rst,
    input  wire [15:0] pixel_data,
    input  wire        trigger,
    output wire        uart_tx_line,
    output reg         busy
);
    reg  [7:0] tx_data;
    reg        tx_send;
    wire       tx_busy;

    uart_tx #(.BAUD_DIV(868)) u_uart (
        .clk(clk), .rst(rst),
        .data_in(tx_data), .send(tx_send),
        .tx(uart_tx_line), .busy(tx_busy)
    );

    function [7:0] hex_char(input [3:0] nibble);
        case (nibble)
            4'h0:hex_char="0"; 4'h1:hex_char="1"; 4'h2:hex_char="2"; 4'h3:hex_char="3";
            4'h4:hex_char="4"; 4'h5:hex_char="5"; 4'h6:hex_char="6"; 4'h7:hex_char="7";
            4'h8:hex_char="8"; 4'h9:hex_char="9"; 4'hA:hex_char="A"; 4'hB:hex_char="B";
            4'hC:hex_char="C"; 4'hD:hex_char="D"; 4'hE:hex_char="E"; 4'hF:hex_char="F";
            default: hex_char="?";
        endcase
    endfunction

    reg [7:0] msg [0:9];
    reg [3:0] char_index;
    reg [3:0] state;
    localparam S_IDLE=4'd0, S_LOAD=4'd1, S_WAIT_TX=4'd2,
               S_SEND=4'd3, S_NEXT=4'd4, S_DONE=4'd5;
    reg [15:0] pixel_latch;

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            state <= S_IDLE; busy <= 0; tx_send <= 0;
            tx_data <= 0; char_index <= 0; pixel_latch <= 0;
        end else begin
            tx_send <= 1'b0;
            case (state)
                S_IDLE: begin
                    busy <= 1'b0;
                    if (trigger) begin
                        pixel_latch <= pixel_data; busy <= 1'b1; state <= S_LOAD;
                    end
                end
                S_LOAD: begin
                    msg[0]<="P"; msg[1]<="X"; msg[2]<=":"; msg[3]<=" ";
                    msg[4]<=hex_char(pixel_latch[15:12]);
                    msg[5]<=hex_char(pixel_latch[11:8]);
                    msg[6]<=hex_char(pixel_latch[7:4]);
                    msg[7]<=hex_char(pixel_latch[3:0]);
                    msg[8]<=8'h0D; msg[9]<=8'h0A;
                    char_index <= 0; state <= S_SEND;
                end
                S_SEND: if (!tx_busy) begin
                    tx_data <= msg[char_index];
                    tx_send <= 1'b1; state <= S_WAIT_TX;
                end
                S_WAIT_TX: if (!tx_busy && !tx_send) state <= S_NEXT;
                S_NEXT: if (char_index == 4'd9) state <= S_DONE;
                        else begin char_index <= char_index + 1; state <= S_SEND; end
                S_DONE: begin busy <= 1'b0; state <= S_IDLE; end
                default: state <= S_IDLE;
            endcase
        end
    end
endmodule
```

**Module description:**
Wraps `uart_tx` to print a single 16-bit pixel value as a human-readable ASCII line: `"PX: AABB\r\n"`, where `AABB` is the hex representation of the latched pixel. A small FSM walks through a 10-character message array, pushing each byte to `uart_tx` and waiting on `tx_busy` before sending the next. Used only by the debug path that snapshots one pixel per frame.

### Module : `top`

**Module code:**
```verilog
module top (
    input  wire        clk,            // 100 MHz Basys 3 crystal
    input  wire        btnC,           // active-high reset

    // OV7670
    input  wire        cam_pclk,
    input  wire        cam_vsync,
    input  wire        cam_href,
    input  wire [7:0]  cam_data,
    output wire        cam_xclk,
    output wire        cam_scl,
    output wire        cam_sda,
    output wire        cam_pwdn,
    output wire        cam_rst,

    // UART debug
    output wire        uart_txd,

    // Switches: filter mode + channel mask
    input  wire [4:0]  sw,

    // VGA
    output wire        vga_hs,
    output wire        vga_vs,
    output wire [3:0]  vga_r,
    output wire [3:0]  vga_g,
    output wire [3:0]  vga_b,

    output wire [15:0] led
);
    wire rst = btnC;
    assign cam_pwdn = 1'b0;
    assign cam_rst  = 1'b1;

    // 25 MHz pixel clock — shared between OV7670 XCLK and VGA pipeline
    wire pclk_25;
    clk_div u_clk_div (.clk_100mhz(clk), .rst(rst), .xclk(pclk_25));
    assign cam_xclk = pclk_25;

    // SCCB camera configuration
    wire config_done;
    wire sda_out;
    assign cam_sda = sda_out;
    camera_config u_cam_cfg (
        .clk(clk), .rst(rst),
        .scl(cam_scl), .sda(sda_out),
        .config_done(config_done)
    );

    // Frame capture: OV7670 → BRAM port A
    wire [16:0] wr_addr;
    wire [11:0] wr_data;
    wire        wr_en, frame_done;
    frame_capture #(.H_PIXELS(320), .V_PIXELS(240), .ADDR_W(17)) u_frame_cap (
        .clk(clk), .rst(rst), .config_done(config_done),
        .cam_pclk(cam_pclk), .cam_vsync(cam_vsync),
        .cam_href(cam_href), .cam_data(cam_data),
        .wr_addr(wr_addr), .wr_data(wr_data),
        .wr_en(wr_en), .frame_done(frame_done)
    );

    // VGA timing
    wire        hsync_w, vsync_w, video_active;
    wire [9:0]  pixel_x, pixel_y;
    vga_sync u_vga (
        .clk(pclk_25), .reset(rst),
        .hsync(hsync_w), .vsync(vsync_w),
        .pixel_x(pixel_x), .pixel_y(pixel_y),
        .video_active(video_active)
    );

    // 2× pixel doubling + 90° CW rotation + horizontal crop/letterbox
    wire        in_image = video_active && (pixel_x >= 10'd80) && (pixel_x < 10'd560);
    wire [8:0]  img_x   = (pixel_x - 10'd80) >> 1;
    wire [8:0]  img_y   = pixel_y[9:1];
    wire [8:0]  cam_row = 9'd239 - img_x;
    wire [8:0]  cam_col = img_y + 9'd40;
    // read_addr = cam_row * 320 + cam_col, expressed as shifts + adds
    wire [16:0] read_addr = {cam_row[7:0], 8'b0}
                          + {2'b00, cam_row[7:0], 6'b0}
                          + {8'b0, cam_col};
    wire [16:0] addr_b    = in_image ? read_addr : 17'd0;

    // Dual-port frame buffer
    wire [11:0] dout_b;
    frame_buffer u_fb (
        .clk_a(clk), .clk_b(pclk_25),
        .we_a(wr_en), .addr_a(wr_addr), .din_a(wr_data),
        .addr_b(addr_b), .dout_b(dout_b)
    );

    // Register in_image to compensate for 1-cycle BRAM read latency
    reg in_image_d;
    always @(posedge pclk_25) in_image_d <= in_image;

    // Filter mux
    wire [11:0] filt_out;
    filters u_filt (.pixel_in(dout_b), .sw(sw), .pixel_out(filt_out));

    wire [11:0] vga_rgb = in_image_d ? filt_out : 12'h000;
    assign vga_r  = vga_rgb[11:8];
    assign vga_g  = vga_rgb[7:4];
    assign vga_b  = vga_rgb[3:0];
    assign vga_hs = hsync_w;
    assign vga_vs = vsync_w;

    // UART debug path
    wire [15:0] pixel_data;
    wire        pixel_valid;
    pixel_capture u_pix_cap (
        .clk(clk), .rst(rst), .config_done(config_done),
        .cam_pclk(cam_pclk), .cam_vsync(cam_vsync),
        .cam_href(cam_href), .cam_data(cam_data),
        .pixel_data(pixel_data), .pixel_valid(pixel_valid)
    );
    wire uart_busy;
    uart_print u_uart_print (
        .clk(clk), .rst(rst),
        .pixel_data(pixel_data), .trigger(pixel_valid),
        .uart_tx_line(uart_txd), .busy(uart_busy)
    );

    // LED debug: sticky status + frame heartbeat + switch mirror
    reg config_done_r, frame_toggle, vsync_seen, href_seen, pclk_seen;
    reg pclk_r1, pclk_r2, pclk_r3;
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            config_done_r<=0; frame_toggle<=0;
            vsync_seen<=0; href_seen<=0; pclk_seen<=0;
            pclk_r1<=0; pclk_r2<=0; pclk_r3<=0;
        end else begin
            if (config_done) config_done_r <= 1'b1;
            if (frame_done)  frame_toggle  <= ~frame_toggle;
            if (cam_vsync)   vsync_seen    <= 1'b1;
            if (cam_href)    href_seen     <= 1'b1;
            pclk_r1<=cam_pclk; pclk_r2<=pclk_r1; pclk_r3<=pclk_r2;
            if (pclk_r2 && !pclk_r3) pclk_seen <= 1'b1;
        end
    end
    assign led[15] = config_done_r;
    assign led[14] = frame_toggle;
    assign led[13] = vsync_seen;
    assign led[12] = href_seen;
    assign led[11] = pclk_seen;
    assign led[10:5] = 6'b0;
    assign led[4:0]  = sw;
endmodule
```

**Module description:**
Top-level module that wires the whole pipeline together. It

1. Generates the 25 MHz pixel/XCLK clock from the 100 MHz crystal.
2. Boots the OV7670 once via `camera_config` and waits for `config_done`.
3. Captures each frame into the dual-port BRAM through `frame_capture` (port A, 100 MHz).
4. Drives the VGA timing with `vga_sync` (port B clock, 25 MHz) and computes, for each visible screen pixel, the rotated/scaled BRAM read address. The mapping doubles each captured pixel to 2×2 screen pixels, rotates the image 90° CW to compensate for the physical camera orientation, crops 40 rotated rows top and bottom to fit vertically, and letterboxes 80-pixel black bars left and right.
5. Routes the BRAM read output through the `filters` mux selected by `SW[1:0]` / `SW[4:2]` and onto `vga_r/g/b`.
6. Runs an independent debug path: `pixel_capture` snapshots one center-frame pixel which is printed by `uart_print` over USB-UART at 115200 baud.
7. Provides sticky-status LEDs and a frame-rate heartbeat for board-level debugging.
